# 2026-07-30 — Public v0.3.0 release

## Objective

Prepare and publish MQL5 CodeGraph v0.3.0 as a public beta only after token/API, dependency, package,
hosted-CI, and repository-security gates pass.

## Starting state

- Branch and commit: `codex/v0.3.0-release` from `d8a0445`
- Relevant specification: `specs/007-authoritative-reference-corpus/spec.md`
- Known constraints: the repository started private; the authoritative PDFs, generated corpus, Graphify
  output, credentials, caches, and local build artifacts must remain outside version control and release
  artifacts.

## Work completed

- Changed package/dashboard metadata to v0.3.0 public beta and added durable release notes.
- Replaced four divergent runtime version literals with one `version.py` authority shared by package
  exports, CLI output, graph metadata, dashboard health, and HTTP server identification.
- Added backend-scoped child environments to the optional Graphify adapter. Version probing receives only
  runtime variables; extraction additionally receives only the selected backend's endpoint, model, and
  credential variables.
- Kept SHA-1 stable graph identifiers unchanged while explicitly marking the hash as non-security use.
- Upgraded ESLint to 10.8.0 and `@eslint/js` to 10.0.1, eliminating the audited vulnerable development
  dependency paths.
- Added public security, contribution, star/community, contributor, acknowledgement, and bundled
  production-dashboard notice guidance.
- Added [ADR-0009](../decisions/ADR-0009-graphify-credential-isolation.md) for the external credential and
  executable trust boundary.

## Decisions

- Provider credentials are ambient only at the final explicitly authorized Graphify extraction process;
  they are not inherited by version probing or unrelated backends and do not become command arguments,
  manifests, structured errors, or lifecycle records.
- Graphify remains an operator-selected executable and is not represented as a sandboxed component.
- GitHub visibility, secret scanning, push protection, dependency alerts, private vulnerability
  reporting, hosted CI, and public artifact installation are release gates rather than optimistic
  documentation claims.

## Risks and unresolved questions

- GitHub visibility and hosted security controls cannot be verified until the release candidate is merged
  and the repository is switched from private to public.
- The final tag artifacts must be rebuilt from the merged commit; candidate checksums are not final release
  checksums.
- The external Graphify executable can access resources permitted to its OS identity. Environment
  filtering reduces ambient credential exposure but is not process or filesystem sandboxing.
- Public installation through the versioned GitHub Release URL remains unverified until the release asset
  exists.

## Next objective

Update the directed Graphify index, merge the release candidate through all required hosted checks, enable
and verify GitHub public security controls, then tag, publish, and clean-install v0.3.0 from its public URL.
